02The flow

The client sees the return before they ask about it.

A returned delivery surfaces three places at once: a counter at the top, a status pill in the row, and a focused drawer that puts the waybill, the delivery ID, and the photo proof on the same screen. No PDF emails, no follow-up tickets.

01Deliveries · returns surfaced
Returns count alongside every other status.

A new "Returned" counter joins the existing five. Rows carry a "Returned" or "Partial return" pill where they used to read "Completed". The accent purple appears only on the new state — every other column stays editorial.

02Return detail · drawer
One row, one drawer — waybill, delivery ID, and proof on the same screen.

Clicking any return-flagged row slides a 560px drawer over the list. The client never leaves the page. Identity sits at the top in a 2×2 grid so it can be copied, scanned, or pasted into a follow-up message without scrolling.

Identity (waybill + delivery ID) is the first block so the client can act on it without reading any further. Photo proof is the second block — three frames captioned with time and GPS, never floating. Notes and activity follow. The drawer dismisses with the close button or the scrim; the list is exactly where the user left it.

The list scales to 6 statuses; the drawer scales to multiple returns per delivery (timeline accumulates). Photo enlargement and dispute submission are next-iteration scope. See returns-mockup-rider-v1.html for the upstream rider flow.
