Catatan untuk engineer & tim internal — Phase 0 (Ekspor-Impor)

Scope prototipe ini = khusus Phase 0 Ekspor-Impor, happy-flow (evidence-driven compliance: get-in/out wajib foto, balik empty wajib, no. kontainer via input manual driver). Detail lengkap + tiket + AC di PRD_4W_Driver_App; alur di Flow_4W_Driver_Journey.
Coba prototype: pilih SHP-EXIM-01072 (Import) atau -01079 (Export) → “Mulai pengiriman” → checklist K3 + foto kondisi kendaraan → runner (geser tiap transisi; foto hanya saat langkah bertanda foto) → foto kondisi akhir → ringkasan. Ketuk ikon sinyal kanan-atas = simulasi offline.
Yang dipangkas di Phase 0 (keputusan meeting 29 Jul)
  • Gate pass = timestamp saja, TANPA foto (ide unggah dari galeri dibatalkan). Gate-in & gate-out TETAP foto real-time (watermark jam + lokasi aktual) — konfirmasi Ops 30 Jul.
  • Foto wajib hanya: kontainer & seal, barang (bongkar/muatan), surat jalan, odometer, kontainer di CY. (Kamera saja, ber-watermark.)
  • No. kontainer tidak wajib diinput ke sistem di awal (sering berubah di lapangan — rusak/ditolak); acuan = surat jalan. No/seal dari DO = referensi di kartu kontainer, driver tetap foto fisik.
  • Dihilangkan: lapor anomali/kendala, fitur gagal/failure, shifting/ganti driver, layar “balik ke pool”, tampilan target lead time, general shipment, preview V1, menu coming-soon. Kendala sistem/aplikasi → CS Dash (pesan template otomatis); kendala operasional → Grup WA ops (biar cepat eskalasi).
  • Terminologi: “Get out Patimban” → “Mulai Berangkat” (generik).
Alur tervalidasi — Pickup · Delivery · Drop
  • Import: Pickup di pelabuhan (antri/dapat gate pass + foto gate-in/out + kontainer & seal) → Delivery/bongkar di customer (foto barang + surat jalan) → Drop kontainer kosong di CY (WAJIB).
  • Export: Pickup di depo (mulai berangkat → foto kontainer kosong) → Pickup/loading di customer (foto muatan + surat jalan) → Drop full container di CY.
  • Label ke driver = Pickup/Delivery/Drop; klasifikasi POP/POD hanya internal (PRD), tak ditampilkan.
Spine — bookend tiap trip
  • Checklist pra-trip (dokumen + tools + SOP K3 + pernyataan tanggung jawab) — tombol Mulai terkunci sampai lengkap; item di-tap satu-satu (bukan bulk).
  • Foto kondisi kendaraan awal & akhir: selfie + 4 sisi + kondisi bak muatan + odometer (foto + ketik angka, dua-duanya wajib). Penutup trip = foto kondisi akhir di lokasi terakhir — tanpa navigasi “balik ke pool”.
Integritas jam & aksi
  • Jam = waktu ketuk (server-verified, non-backdate); geofence prompt saat masuk lokasi; reminder lembut per-stage (config); flag anti-bulk/proxy ke Ops.
  • Slide-to-confirm untuk transisi (cegah kepencet); tap untuk buka kamera. Foto kamera saja (no galeri), ber-watermark, per langkah.
  • Timer tunggu gate pass jalan otomatis di gate pelabuhan = bukti waktu proses (biaya inap/dispute); durasi dilipat ke timestamp tahap + ringkasan. Tanpa target lead time.
Kebutuhan back-end (paralel, di luar app)
  • Update status ke klien tiap 2 jam → butuh dashboard/akses data; bila dashboard belum siap, export Excel dari back-end = solusi interim MVP.
  • Field baru: workflowCategory · opsNote · container · PIC per stop · Locations master. Delivery exim dibuat dari platform internal (https://nexusdrive.lovable.app/requests/new), namun perlu penambahan input order nomor dari client (contoh: AGL Order No). 1 unit = 1 driver, tanpa helper.
Konfirmasi Ops (30 Jul) & catatan
  • ✅ Balik kontainer kosong ke CY (import) = WAJIB — jadi stop tetap (bukan opsional/pilihan driver). Dikonfirmasi Ops.
  • ✅ Gate-in & gate-out = foto real-time (watermark jam + lokasi aktual); gate pass = timestamp saja. Dikonfirmasi Ops.
  • No. kontainer direkam via input manual driver di TIAP foto kontainer (mutable — nangkep kalau kontainer diganti; checkbox “sama seperti tahap sebelumnya” utk reuse tanpa ketik ulang). No. seal tidak diketik — cukup dari foto kontainer & seal. Bukan OCR. Admin bisa update di platform.
  • Booking ID / Ref customer TIDAK ditampilkan di driver app — itu kebutuhan tracking client di Dash Link (client search/filter shipments). Driver cukup pakai kode shipment. Field-nya tetap ada di sistem utk Dash Link. Key tracking final client masih TBD — validasi langsung ke client. Dependency Dash Link (POV client).
  • Stop-based (konsep engineer): tiap stop = main type Pickup / Drop-off + aktivitas (gate/foto/bongkar/loading) di dalamnya. Label driver (English) Pickup · Delivery · Drop. Import = Pickup · Delivery · Drop; Export = Pickup · Pickup · Drop (multi-pickup existing). Aturan label: Delivery = serah-terima barang (bongkar + surat jalan, POD); Drop = taruh/kembalikan kontainer di yard/port tanpa serah-terima barang (tetap DROPOFF/POD). "Drop" BUKAN grup Return (Return = jalur gagal/retur barang). Cek §6.6 PRD.
  • Sudah di-align ke data model engineer (31 Jul: multidrop-erd + shipapi): exim = type=DIRECT_4W → routes → route_stops (PICKUP/DROPOFF) → stop_proofs (POP/POD, per-attempt) via steppers/stepper_fields (IMAGE/TEXT/NUMBER). Aktivitas per-step = stepper/MILESTONE; status stop = custody STATUS (v2). Tracking client = waybill + bookingId (= AGL Order No). Create: import=/multi-drop, export=/multi-pickup. Urutan flow SOP tidak berubah — detail granularity step (status vs stepper field vs stop) tunggu final arsitektur engineer. Cek §5C PRD.
  • Rute yang direkomendasikan tampil di detail (awareness kendaraan besar) + tombol buka Google Maps (origin→next). Tanpa turn-by-turn in-app. (Catatan rute dinamis di-hide dulu — field-nya belum ada di platform internal.)
  • Notifikasi hambatan ke customer (macet/ban bocor) ditunda — SOP siapa yang kirim (driver vs Ops) belum matang.
  • ⏳ Antrean gate pass di CY export — tetap dipasang (konsisten dgn import & bukti waktu berharga); tinggal konfirmasi Ops apakah benar antre.
  • Target demo ke driver: TBC (W2 atau W3 Aug).
  • Penyesuaian final V0 (3 Agu · Stepper/Form meeting): (1) Runner screen = peta + bottom sheet geser (konsisten dgn Home) — peta selalu terlihat, pin bernomor per stop; sheet bisa geser naik (expanded) / turun (peek). Navigasi = Google Maps (tombol map peta). (2) Stepper-first / form-direct: stop >1 langkah → tampilkan daftar langkah dulu (timeline runner); stop 1 langkah → langsung form. (3) No. kontainer TANPA auto-fill — ketik ulang tiap tahap (akurasi per titik); checkbox "sama seperti sebelumnya" = P2, tidak di V0. (4) Foto kendaraan awal = acuan — di akhir trip cuma odometer akhir wajib; foto sisi opsional (bila ada kerusakan).
  • Flow status/activity masih menunggu konfirmasi final arsitektur sistem dari engineer. Secara UI, activity/status mungkin ada sedikit adjustment nantinya — tapi tidak akan mengubah urutan flow SOP Ops. (TBC)
